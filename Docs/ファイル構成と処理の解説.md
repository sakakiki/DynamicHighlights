# ファイル構成と処理の解説

この資料では、実験システムの各ファイルが **何のためにあり、どんな処理をしているか** を説明します。
コードを読む前に、まずこの資料で全体像をつかんでください。各ファイルの中にも詳しいコメントを書いてあります。

---

## 1. システム全体の構成

### 1.1 データの流れ

HMD の向きが、どのような計算を経てカメラの向きになるかを示します。

```
 ┌───────────────┐
 │  HMD（Quest）   │  または マウス・キーボードによる模擬（HMD が無いとき）
 └───────┬───────┘
         │ 頭の回転（Quaternion）
         ▼
 ┌────────────────────┐
 │ HeadPoseSource.cs    │  頭の回転を取得する
 └───────┬────────────┘
         │
         ▼
 ┌──────────────────────────────────────────────────────────┐
 │ GazeDirectionController.cs（心臓部）                          │
 │                                                              │
 │  ① ヨー角を取り出す                                          │
 │  ② 実視線方向 r = 開始時の正面からの角度                     │
 │  ③ 角速度 ω  ← AngularVelocityEstimator.cs（スライド7）      │
 │  ④ 傾き s    ← HighlightMapping.SlopeFromOmega（スライド7）  │
 │  ⑤ 仮想視線方向 v ← HighlightMapping.MapAbsolute（スライド5）│
 │  ⑥ カメラの向き = (v − r) だけ回す × HMD の回転               │
 └───────┬──────────────────────────────────────────────────┘
         │ r, v, ω, s, c
         ├──────────────► ExperimentLogger.cs（CSV に保存）
         ├──────────────► DebugHud.cs（PC 画面に表示）
         ▼
 ┌───────────────┐
 │  Main Camera     │  → HMD に映る景色
 └───────────────┘
```

## 2. 各ファイルの解説

### 2.1 `Core/HighlightMapping.cs` — 数式のまとめ

| 項目 | 内容 |
|---|---|
| 役割 | 視線方向制御の数式をすべてまとめた static クラス。数値を入れると数値が返るだけで、シーンには触らない |
| 対応スライド | 4（端点）、5（折れ線）、7（s(ω)） |
| 使われる場所 | GazeDirectionController、DebugHud、MappingGraphExporter、テスト |

**主な関数**

| 関数 | 処理内容 | 式 |
|---|---|---|
| `ComputeEndpoints(φ, w, s)` | 見どころ範囲の端点を計算 | v₁ = φ − w/2, v₂ = φ + w/2, r₁ = φ − w/(2s), r₂ = φ + w/(2s) |
| `MapAbsolute(r, φ, w, s, symmetric)` | r から v を直接計算（制御一定・動的制御の両方で使う） | r < r₁：v = r·v₁/r₁<br>r₁ ≦ r ≦ r₂：v = s(r − φ) + φ<br>r₂ < r：v = r(90 − v₂)/(90 − r₂) − 90(r₂ − v₂)/(90 − r₂) |
| `SlopeFromOmega(ω, ω₀, s₀)` | 角速度から傾き s を計算 | \|ω\| ≦ ω₀：s = −\|ω\|(1 − s₀)/ω₀ + 1<br>\|ω\| > ω₀：s = s₀ |
| `ControlStrength(s, s₀)` | 制御強度 c | c = (1 − s)/(1 − s₀) |
| `MinimumValidSlope(φ, w)` | 折れ線が成り立つ s の下限 | s > w / (2·min(φ, 90 − φ)) |
| `Validate(φ, w, s₀)` | パラメータが正しいかのチェック | — |
| `WrapAngle(a)` | 角度を −180〜180 に収める | — |
| `YawOf(q)` / `PitchOf(q)` | 回転から左右の向き・上下の向きを取り出す | — |

**左右対称の処理**：`symmetric = true` のとき、|r| ≦ 90° では v = sign(r)·F(|r|) とします。
つまり右側の折れ線を原点で 180° 回したものが左側に付きます（−φ にも見どころ範囲ができる）。

### 2.2 `Core/AngularVelocityEstimator.cs` — 角速度の推定

| 項目 | 内容 |
|---|---|
| 役割 | 直近 N フレームの r から角速度 ω を推定する |
| 対応スライド | 7 |
| 使われる場所 | GazeDirectionController |

**処理の流れ**

1. `AddSample(時刻, r)` でデータを「リングバッファ」（N+1 個分の配列を使い回す仕組み）に追加する
2. k = 1〜N について次を計算する
   - v_k = (r_{k−1} − r_k) / Δt_k（角度の差は `Mathf.DeltaAngle` で計算するので、180° をまたいでも正しい）
   - a_k = 現在時刻 − (区間 k の中間時刻)
   - w_k = Δt_k · e^(−a_k/τ)
3. ω = Σ w_k v_k / Σ w_k

**パラメータの意味**：τ が小さいと新しいデータばかり重視されて反応は速いがガタつきやすく、τ が大きいとなめらかだが反応が遅くなります。

### 2.3 `ExperimentConfig.cs` — 設定ファイル

| 項目 | 内容 |
|---|---|
| 役割 | 実験パラメータをまとめた ScriptableObject（.asset ファイルとして保存されるデータ） |
| 中身 | φ, w, 左右対称, s₀, ω₀, τ, N, 練習試行の有無, 制限時間, 注視判定の角度, 注視中の色変更 |
| その他 | 条件の種類 `ViewingCondition`（NoControl / FixedControl / DynamicControl）もこのファイルで定義 |

Inspector で値を変えると `OnValidate()` が自動で呼ばれ、パラメータに問題があれば Console に警告が出ます。

### 2.4 `HeadPoseSource.cs` — 頭の向きの取得

| 項目 | 内容 |
|---|---|
| 役割 | HMD の回転を取得する。HMD が無いときはマウス・キーボードで模擬する |
| HMD の読み方 | Input System の `XRHMD` デバイスの `centerEyeRotation`（両目の中心の回転） |
| 模擬操作 | マウス右ドラッグ：自由に回す / ←→：30°/秒 / Shift+←→：150°/秒 |
| テスト用 | `SetSimulatedRotation(yaw, pitch)` で模擬の向きを直接設定できる（PlayMode テストで使用） |

### 2.5 `GazeDirectionController.cs` — 心臓部

| 項目 | 内容 |
|---|---|
| 役割 | 毎フレーム r → ω → s → v を計算し、カメラの向きに反映する |
| 外から呼ぶ関数 | `Recenter()`（いまの向きを正面にする）、`SetCondition(条件)` |
| 外から読める値 | `RealYaw`（r）、`VirtualYaw`（v）、`Omega`（ω）、`Slope`（s）、`ControlStrength`（c）、`Pitch`、`Offset`（v − r） |

**条件ごとの s と v**

| 条件 | s | v の計算 |
|---|---|---|
| NoControl（通常のVR視聴） | 1 | v = r |
| FixedControl（元研究） | s₀ | v = F(r; s₀) |
| DynamicControl（本研究） | s(ω) | v = F(r; s(ω)) |

**カメラの向きの決め方**

```
カメラの回転 = AngleAxis(v − r − 開始時のヨー, 上向きの軸) × HMD の回転
```

HMD の生のヨー角は「開始時のヨー + r」なので、カメラのヨー角は
（v − r − 開始時のヨー）+（開始時のヨー + r）= **v** になります。
上下（ピッチ）と首のかしげ（ロール）は HMD のままです。

### 2.6 `TargetObject.cs` — 鑑賞対象

| 項目 | 内容 |
|---|---|
| 役割 | 鑑賞対象のオブジェクト。表示する文字の変更と、到達時間・注視時間の計測 |
| 注視の判定 | カメラの正面方向とオブジェクトへの方向のなす角が `gazeAngleThreshold`（初期値 10°）以内なら「見ている」 |

| 文字 | 試行ごとにランダムな3文字（読み間違えやすい 0/O, 1/I などは除外）。被験者に読み上げてもらうと、ちゃんと見えたかを客観的に確認できる |

### 2.8 `ExperimentLogger.cs` — データの保存

| 項目 | 内容 |
|---|---|
| 役割 | CSV ファイルに実験データを保存する |
| 保存先 | プロジェクト直下の `ExperimentData/` |

### 2.9 `ExperimentFlow.cs` — 実験の進行役

**状態の移り変わり（ステートマシン）**

```
 Setup ──「実験を開始」──► Ready ──Space──► Running ──Space/制限時間──┐
   ▲                        ▲                                          │
   │                        └──────── 次の試行がある ◄───────────────┤
   └─「次の被験者へ」── Finished ◄──── 全試行が終わった ◄─────────────┘
```

| 状態 | 何が起きているか |
|---|---|
| Setup | PC 画面で被験者ID を入力。条件の順番がプレビューされる |
| Ready | VR 内に「正面を向いてください」と表示。制御は NoControl |
| Running | 開始時にリセンターし、その試行の条件で制御。文字を表示し、毎フレームログを記録 |
| Finished | 終了メッセージを表示 |

**条件の順番（カウンターバランス）**：3条件の並べ方6通りを、被験者ID の数字で割り当てます（P01 → 1番目、P02 → 2番目、…、P07 → 1番目）。6の倍数の人数を集めると、すべての並べ方が同じ回数になります。

**OnGUI**：PC 画面の左上に実験者パネルを描きます（HMD には映りません）。試行中は、各オブジェクトに表示中の文字が出るので、被験者の読み上げと照合できます。

### 2.10 `Debug/DebugHud.cs` — 動作確認用の表示

PC 画面の右上に r, v, v − r, ω, s, c と r-v グラフを表示します（H キーで切り替え）。

- 水色の線：いまの s での折れ線（v = F(r; s)）
- 赤い点：いまの (r, v)
- 薄い帯：見どころ範囲（v₁〜v₂）

動的制御では、頭を止めると s が 1 に戻って線の形が変わるため、赤い点が上下に動きます（急停止で視界が少し戻る既知の挙動が、これで目に見えます。4章）。

### 2.11 `Debug/CameraCheckDriver.cs` — カメラ挙動チェック（実行時の部分）

テストを実行せずに、Play 中にカメラの動きを目で見て確かめるための動作確認用コンポーネントです。
画面の表示は `Editor/CameraCheckWindow.cs`（2.14）が担当し、こちらは「動かす」「記録する」を担当します。

| 機能 | 処理内容 |
|---|---|
| 頭の動きの自動再生 | `CreatePatterns(φ)` で5つのパターン（ゆっくり往復／速く往復／速く回して急停止／速く通り過ぎてゆっくり戻る／見どころ付近を見回す）を作る。`Play()` で再生すると、毎フレーム `Mathf.MoveTowards` で目標の角度に近づけ、`HeadPoseSource.SetSimulatedRotation()` で頭の向きを設定する。HMD 接続中は再生できない |
| 履歴の記録 | LateUpdate で毎フレーム r, v, s, ω を List に追加し、`historySeconds`（6秒）より古いものを消す。`CopyHistory()` で渡す |
| Scene ビューの補助線 | `OnDrawGizmos` で、カメラから v（赤）、r（灰）、見どころ範囲の端（黄）の線を描く |
| スロー再生・一時停止・コマ送り | `SetPlaybackSpeed()`・`SetPaused()`・`StepOneFrame()`・`ResetTime()` で `Time.timeScale` を変える。コマ送りは `Time.timeScale` を1フレームだけ再生速度にし、LateUpdate で 0 に戻す。HMD 接続中は使えず、`OnDisable` で必ず等速に戻す |

**スロー再生の仕組み（「角速度は速い、映像は遅い」）**

| 処理 | 使う時計 | スロー再生（×0.25）のとき |
|---|---|---|
| 自動再生の頭の動き（`Time.deltaTime`） | ゲーム内時間 | 現実の時間ではゆっくり動く ＝ 映像がスロー |
| 角速度 ω の計算（`GazeDirectionController` の `Time.timeAsDouble`） | ゲーム内時間 | 頭の角度の変化 ÷ ゲーム内の経過時間 なので、本来の速さ（150°/秒）のまま |
| 履歴・グラフの横軸（`Time.time`） | ゲーム内時間 | グラフの形は等速と同じ |

ふだん（`Time.timeScale = 1`）はゲーム内時間と現実の時間は同じなので、実験の本番の計算には影響しません。
試行の開始時には ExperimentFlow が `Time.timeScale = 1` に戻します。

一時停止中は時間が進まないので、履歴は同じ時刻のデータを増やさず、最後の1つを置き換えます（止めている間にマウスで動かした分も図に出るようにするため）。

**一時停止中の ω**：`GazeDirectionController` は、ゲーム内時間が前回の記録から進んでいないフレームでは、角速度の計算機（AngularVelocityEstimator）に記録しません。
もし記録すると「同じ時刻のデータ」ばかりになって速さが計算できず ω = 0 → s = 1 となり、止めているのに視界が動いてしまうためです。
s は毎フレーム「保っている ω」から計算し直すので、一時停止中に条件を切り替えると s と v はその条件のものに変わります。
なお、条件を切り替えても角速度の履歴は消しません（ω は頭の動きで決まり、条件とは関係ないため）。

**パターンの作り方**：1つのパターンは `MotionStep`（回す先の角度・速さ・止まる時間・説明）の並びです。
新しいパターンを追加したいときは、`CreatePatterns()` の中に `new MotionPattern { … }` を1つ書き足してください。

**実行順**：`[DefaultExecutionOrder(50)]` なので、HeadPoseSource（0）の Update の後に頭の向きを上書きし、
GazeDirectionController（-100）の LateUpdate の後に履歴を記録します。

### 2.14 `Editor/CameraCheckWindow.cs` — カメラ挙動チェック（ウィンドウの部分）

Play 中のカメラの動きを、ボタン・図・グラフで確かめるエディタウィンドウです（EditorWindow）。

| 部分 | 処理内容 |
|---|---|
| ① 条件 | ボタン（通常／制御一定／動的制御）で `GazeDirectionController.SetCondition()` を呼ぶ。試行中は `EditorGUI.DisabledScope` で押せなくする |
| ② 自動再生 | ボタンで `CameraCheckDriver.Play()` を呼ぶ |
| ③ スロー再生 | ボタンで `CameraCheckDriver.SetPlaybackSpeed()`（等速・×0.5・×0.25・×0.1）、`SetPaused()`、`StepOneFrame()`、`ResetTime()` を呼ぶ。試行中・HMD 接続中は押せない |
| 上から見た図 | `Handles.DrawAAPolyLine`（線）、`Handles.DrawAAConvexPolygon`（扇形の塗りつぶし）、`Handles.DrawSolidDisc`（点）で描く。上が 0°、右が +90°。GUI の座標は下に行くほど y が大きいので、`PointOnCircle()` で y をマイナスにしている |
| 時間変化のグラフ | `CameraCheckDriver.CopyHistory()` で受け取った履歴を、横軸＝時間・縦軸＝角度の折れ線にする |
| 描き直し | `Update()` で Play 中は毎回 `Repaint()` を呼ぶ。描画は `EventType.Repaint` のときだけ行う |

シーンに CameraCheckDriver が無いときは、Play の間だけ一時的に追加します。

## 3. 1フレームの中の処理の順番

Unity は1フレームの中で、次の順にスクリプトの関数を呼びます。

```
 1. Update（全スクリプト）
      HeadPoseSource.Update   … マウス・キーボードの模擬入力を読む
      ExperimentFlow.Update   … 実験者のキー操作（Space, R, 1/2/3）を読む
      DebugHud.Update         … H キーを読む

 2. LateUpdate（全スクリプト。実行順の指定 [DefaultExecutionOrder] が小さいものから）
      GazeDirectionController.LateUpdate（-100）
          … r を求め、ω を更新し、s を決め、v を計算してカメラに反映
      ExperimentFlow.LateUpdate（0）
          … 注視しているオブジェクトを判定し、ログに1行書く

 3. BeforeRender（描画の直前。HMD 接続時のみ）
      GazeDirectionController.OnInputAfterUpdate
          … HMD の最新の向きで r と v だけを計算し直してカメラに反映（遅延を減らすため）

 4. 描画 → HMD に表示
      OnGUI（ExperimentFlow, DebugHud）… PC 画面にパネルを描く
```

**なぜ BeforeRender でもう一度計算するのか**：HMD の向きは描画の直前にもう一度更新されます。LateUpdate の時点の向きのまま描くと、頭の動きと映像がわずかにずれ、酔いの原因になります。ω と s は LateUpdate で計算したものを使い回し、r と v だけを最新にしています。

## 4. 急停止したときの視界の戻り（既知の挙動）

動的制御では、そのときの s を使った折れ線 v = F(r; s) で、「r がいくつなら v はいくつ」を直接決めます（スライドの式どおりの絶対写像）。

**既知の挙動**：s が変わると折れ線の形も変わります。そのため、**頭が止まっていても v が動くことがあります**。

**数値例**（φ = 45°, w = 20°, s₀ = 0.5）

| 状況 | r | s | v | 視界 |
|---|---|---|---|---|
| 速く回している途中 | 25° | 0.5 | 35° | — |
| 急に止まる | 25° | 1.0 | 25° | **頭は止まっているのに、視界が 10° 逆向きに戻る** |

ω は直近数フレームの重み付き平均なので、s は一瞬ではなく短い時間（τ = 0.05 秒程度）をかけて 1 に戻ります。

### 4.1 この挙動への対応

この研究の焦点は「見どころ制御の動的変化」であり、「完全に実用的なシステムの構築」ではありません。そこでシステムでは対策をせず、**実験の前に被験者へ口頭で伝える**ことにしました（教授の判断、2026-11-24）。
説明文の例は「使い方ガイド」の 4.4 にあります。

- 挙動の大きさは自動テスト `止まったままsが戻るとvが動く_既知の挙動` で確かめています（10°）。
- カメラ挙動チェックの「速く回して急停止」を再生すると、目で見て確認できます。

### 4.2 廃止した方式B について

以前は、この挙動を避けるために「方式B（増分ゲイン方式：v ← v + g(v; s)·Δr）」も実装し、切り替えられるようにしていました。
上の判断によって方式B は廃止しました。コードと解説は `Archive/方式B_増分ゲイン/` に保管しています（Unity は読み込みません）。
