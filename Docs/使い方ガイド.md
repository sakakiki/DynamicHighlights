## 2. 初回のセットアップ

### 2.1 プロジェクトを開く

1. Unity Hub で `DynamicHighlights` フォルダを開きます。
2. 初回はパッケージの読み込みに数分かかります。

### 2.2 XR（OpenXR）の設定（設定済み。やり直すときだけ）

設定はすでに済んでいます。設定が壊れた場合や別の PC で作り直す場合は、次を実行します。

- メニュー **DynamicHighlights → XR（OpenXR）を設定**

これで次の設定が自動で行われます。

| 設定場所（Edit → Project Settings） | 内容 |
|---|---|
| XR Plug-in Management → Windows タブ | OpenXR にチェック |
| XR Plug-in Management → OpenXR | Render Mode：Single Pass Instanced、Interaction Profile：Oculus Touch Controller Profile |

実行後、**XR Plug-in Management → Project Validation** に警告が出ていないか確認してください。
警告があれば「Fix All」ボタンで直せることが多いです。

### 2.3 実験シーンの作成（作成済み。作り直すときだけ）

`Assets/Scenes/Experiment.unity` は作成済みです。作り直したいときは次を実行します。

- メニュー **DynamicHighlights → 実験シーンを作成**

> **注意**：作り直すと、シーン上で手作業で変更した内容（オブジェクトの位置など）は消えます。
> 設定ファイル（`Assets/Settings/ExperimentConfig.asset`）の値はそのまま残ります。
> 設定ファイルの φ や「左右対称」を変えたときは、オブジェクトの配置を合わせるために作り直してください。

### 2.4 Quest Link の準備

1. PC で **Meta Quest Link アプリ** を起動し、Quest をケーブル（または Air Link）でつなぎます。
2. アプリの **設定 → 一般 → OpenXR ランタイム** で、「Meta Quest Link を有効な OpenXR ランタイムとして設定」を押します。
   （SteamVR などが有効になっていると、Unity から Quest につながりません）
3. Quest の中で Link を開始し、Link のホーム画面が見えていれば準備完了です。

## 3. HMD なしでの動作確認

HMD をかぶらなくても、PC だけで動きを確認できます。プログラムを変更したときは、まずここで確認してください。

### 3.1 起動

1. `Assets/Scenes/Experiment.unity` を開きます（Project ウィンドウでダブルクリック）。
2. 上の ▶（Play）ボタンを押します。
3. Game ビューの左上に **実験者パネル**、右上に **デバッグ表示** が出ます。

### 3.2 頭の向きの模擬操作

HMD が接続されていないときは、マウスとキーボードで頭の動きを模擬できます（Game ビューをクリックしてから操作）。

| 操作 | 動き |
|---|---|
| マウス右ボタンを押しながら動かす | 頭を左右・上下に回す |
| ← / → キー | 30°/秒 でゆっくり回す（s ≈ 1 に近い状態の確認） |
| Shift ＋ ← / → キー | 150°/秒 で速く回す（ω ＞ ω₀ で s = s₀ になる状態の確認） |
| R キー | リセンター（いまの向きを正面にする） |
| H キー | デバッグ表示の表示/非表示 |

### 3.3 デバッグ表示の見方

| 表示 | 意味 |
|---|---|
| 入力 | HMD を使っているか、マウス模擬か |
| 条件 / 方式 | いまの視聴条件と、動的制御の方式（A/B） |
| r / v | 実視線方向 / 仮想視線方向 [度] |
| v − r | 実際の向きと画面の向きのズレ [度] |
| ω | 角速度 [度/秒] |
| s / c / g | 傾き / 制御強度 / いまの位置でのゲイン |
| グラフ | 横軸 r・縦軸 v。水色の線がいまの s での折れ線、赤い点がいまの (r, v)、薄い帯が見どころ範囲 |

### 3.4 条件ごとの動きを試す

再生中に、Hierarchy の **ExperimentSystem** を選び、Inspector の **Gaze Direction Controller → Condition** を変えると、条件を手で切り替えられます。
（次の 3.5 の「カメラ挙動チェック」ウィンドウを使うと、ボタンで切り替えられて、頭の動きも自動で再生できます）

| 確認すること | 操作 | 期待される結果 |
|---|---|---|
| 通常のVR視聴 | Condition = NoControl | v − r が常に 0 |
| 制御一定 | Condition = FixedControl で → キーを押し続ける | 見どころ（φ）付近で v の進みが遅くなる（グラフの赤い点が水色の線の上を動く） |
| 動的制御・方式A | Condition = DynamicControl、設定ファイルの Dynamic Method = Absolute。Shift + → で 25° 付近まで回してキーを離す | **キーを離した瞬間に v が戻る**（赤い点が縦に動く）。これが「視界が勝手に動く」問題 |
| 動的制御・方式B | Dynamic Method = Incremental で同じ操作 | キーを離すと v も止まる（赤い点が動かない） |

### 3.5 カメラ挙動チェック ウィンドウ（おすすめ）

テストを実行しなくても、カメラの動きを図とグラフで確かめられる専用のウィンドウです。
3.4 の操作も、このウィンドウならボタン1つでできます。

**開き方**：メニュー **DynamicHighlights → カメラ挙動チェック**
（Play していないときは「▶ Experiment シーンを開いて再生」ボタンが出ます）

ウィンドウのタブをドラッグして **Game ビューの横に並べる** と、景色と図を同時に見られて便利です。

| 部分 | 内容 |
|---|---|
| ① 条件 | 「通常」「制御一定」「動的・方式A」「動的・方式B」をボタンで切り替え。いまの条件のボタンは水色になる。試行中は押せない |
| ② 頭の動きの自動再生 | 決まった頭の動きを自動で再生する（下の表）。同じ動きを条件だけ変えて何度でも再生できるので、違いを比べやすい。「繰り返す」で最後まで行ったら最初に戻る。「リセンター」で正面に戻す |
| ③ スロー再生 | 映像を ×0.5／×0.25／×0.1 の速さにする。一時停止と「1コマ進む」（コマ送り）もできる。**角速度 ω などは本来の速さで計算される**（下の説明） |
| 数値 | r, v, v − r, ω, s, c |
| 上から見た図 | 上が正面（0°）。**灰色の矢印 = 実際の頭の向き r**、**水色の矢印 = 画面の向き v**。薄い帯は見どころ範囲（v₁〜v₂）、橙の弧はいまの s での頭の向きでの範囲（r₁〜r₂）、点は鑑賞対象のオブジェクト |
| 時間変化のグラフ | 直近6秒の r（灰）・v（水色）・s（黄）。右端がいま。帯は見どころ範囲 |

**自動再生のパターン**（ボタンにマウスを乗せると説明が出ます）

| パターン | 動き | 確かめること |
|---|---|---|
| ゆっくり往復 | 30°/秒 で 0°→90°→0° | 動的制御では s がほぼ 1 のまま（制御が弱い） |
| 速く往復 | 150°/秒 で 0°→90°→0° | 動的制御でも s = s₀ になり、制御一定と同じ動きになる |
| 速く回して急停止 | φ−20°（25°）まで速く回して2秒止まる | **方式A**：止まった後に水色の矢印（v）だけが勝手に戻る。**方式B**：矢印も止まる |
| 速く通り過ぎてゆっくり戻る | 80° まで速く回し、20°/秒 で正面に戻る | **方式B**：正面に戻っても v − r のズレが残る |
| 見どころ付近を見回す | 見どころまで速く回し、±15° をゆっくり見回す | 動的制御では、ゆっくり見回すときに制御が弱まる（グラフの s が 1 に近づく） |

**スロー再生の使い方と仕組み**

速く回すパターン（150°/秒）は一瞬で終わってしまうので、v や s の変化を目で追うのが大変です。
スロー再生にすると、**頭は 150°/秒 で回していることにしたまま**、映像だけをゆっくり見られます。

1. ② で「速く回して急停止」などのパターンを再生する
2. ③ で「×0.25」を押す → 映像が 4 分の 1 の速さになる（ω は 150°/秒 のまま表示される）
3. 気になるところで「⏸ 一時停止」→「1コマ進む」で1フレームずつ確認する
4. 終わったら「元に戻す」（等速・一時停止なし）

仕組み：Unity の `Time.timeScale`（ゲーム内の時間が現実の何倍の速さで進むか）を下げています。
自動再生の頭の動きはゲーム内時間で進むので現実にはゆっくりになり、角速度 ω もゲーム内時間で計算するので本来の速さのままになります。
グラフの横軸もゲーム内時間なので、スロー再生してもグラフの形は等速のときと同じです。

| 注意 | 理由 |
|---|---|
| 試行中（実験の本番）は使えない。試行の開始時には自動で等速に戻る | 試行の時間や注視時間の計測が狂うため |
| HMD 接続中は使えない | 実際の頭の動きは現実の時間で動くので、ω が正しく計算されなくなるため |
| スロー再生中にマウスや←→キーで回すと、速く回したことになる | マウスは現実の速さで動くが、ゲーム内の時間はゆっくり進むため（←→キーはゲーム内時間で動くので、×0.25 なら見た目も 4 分の 1 の速さ） |
| Play を止めると等速に戻る | — |

> Unity のツールバーの ⏸（一時停止）・⏭（コマ送り）ボタンでも止められますが、その間はこのウィンドウの図も止まります。
> ウィンドウの「⏸ 一時停止」なら、止めている間もマウスで頭の向きを変えて図で確認できます。

> **HMD をかぶったときも使えます**：自動再生はできませんが、実際に頭を動かすと図とグラフに表示されるので、
> 実験者が PC 画面でカメラの動きを確認できます。
>
> **Scene ビューでも確認できます**：Play 中に Scene ビューを見ると、カメラから赤い線（v）・灰色の線（r）・黄色の線（見どころ範囲の端）が出ています。
>
> ウィンドウで方式（A/B）を切り替えても、設定ファイルは書き換わりません（Play を止めると元に戻ります）。
> 本番の試行の開始時には、必ず設定ファイルの方式に戻ります。
>
> シーンに CameraCheckDriver（自動再生と履歴の記録を行うコンポーネント）が無いときは、ウィンドウが Play の間だけ一時的に追加します。
> シーンに保存しておきたいときは、Experiment シーンを開いて
> メニュー **DynamicHighlights → 開いているシーンにカメラ挙動チェックを追加** を実行し、シーンを保存（Ctrl+S）してください。

### 3.6 実験の流れを通しで試す

1. 実験者パネルで被験者ID（例：`P01`）を入力し、「実験を開始」を押します。
2. Space キーで試行開始 → しばらく操作 → Space キーで試行終了。これを繰り返します。
3. 終わったらメニュー **DynamicHighlights → 実験データのフォルダを開く** で CSV ができているか確認します。

> 動作確認で作ったデータは、本番のデータと混ざらないように削除しておいてください。

## 4. パラメータの変え方

パラメータは **`Assets/Settings/ExperimentConfig.asset`** にまとまっています。
Project ウィンドウでこのファイルを選ぶと、Inspector に一覧が出ます（項目にマウスを乗せると説明が出ます）。

### 4.1 見どころの設定

| 項目 | 記号 | 初期値 | 説明 |
|---|---|---|---|
| Highlight Direction | φ | 45 | 見どころ方向 [度]。正面が 0°、右回りがプラス |
| Highlight Width | w | 20 | 見どころ範囲 [度]（仮想視線方向上の幅） |
| Symmetric | — | ON | ON：左右対称に制御する（−φ にも見どころ範囲ができる）。OFF：右側（0〜90°）だけ制御する |

### 4.2 動的制御のパラメータ

| 項目 | 記号 | 初期値 | 説明 |
|---|---|---|---|
| Min Slope | s₀ | 0.5 | s の最小値。制御一定の条件ではこの値で固定。**元にした研究の最適値に合わせてください** |
| Omega Threshold | ω₀ | 90 | \|ω\| がこの値 [度/秒] 以上で s = s₀ になる |
| Tau | τ | 0.05 | 角速度の計算で、古いフレームの重みを減らす時定数 [秒]。小さいほど反応が速い |
| Velocity Frame Count | N | 5 | 角速度の計算に使うフレーム数 |
| Dynamic Method | — | Absolute | Absolute：方式A（スライドの式どおり）。Incremental：方式B（頭が止まると視界も止まる） |

### 4.3 パラメータの制約（重要）

折れ線が成り立つためには、次の条件が必要です。

- **w/2 ＜ φ** かつ **w/2 ＜ 90 − φ**（見どころ範囲が 0°〜90° の中に収まる）
- **s₀ ＞ w / (2·min(φ, 90 − φ))**（r₁ が 0° より大きくなる）

例：φ = 45, w = 20 のとき、s₀ は 0.222 より大きくする必要があります。
条件を満たさない値を入れると、Console に警告が出て、デバッグ表示に赤字でエラーが表示されます。

### 4.4 実験の進行の設定

| 項目 | 初期値 | 説明 |
|---|---|---|
| Include Practice Trial | ON | 本番の前に「通常のVR視聴」で練習試行を1回行う |
| Trial Duration Seconds | 0 | 1試行の制限時間 [秒]。0 なら制限なし（Space で終了） |
| Gaze Angle Threshold | 10 | 視野の中心からこの角度以内にあるオブジェクトを「見ている」と判定 [度] |
| Highlight Gazed Target | OFF | 注視中のオブジェクトの色を変える（動作確認用。本番では OFF） |

> 使ったパラメータの値は、試行ごとにまとめファイル（`*_summary.csv`）に自動で記録されます。

### 4.5 オブジェクトの配置を変える

シーン内の **Targets** の下にある `Target_○○` の位置を動かせば、配置を変えられます。
注視の判定は各オブジェクトの位置から自動で計算するので、スクリプトの変更は不要です。
文字の大きさは、各オブジェクトの `LabelCanvas → Label`（Text）の Font Size で変えられます。

## 5. 実験当日の手順

### 5.1 事前の準備（チェックリスト）

- [ ] Quest を充電し、Link でつながることを確認した
- [ ] Meta Quest Link が「有効な OpenXR ランタイム」になっている
- [ ] Quest の境界線（ガーディアン）を「静止」モードにした（その場で回るだけなので）
- [ ] 被験者が回転できる椅子（または立ち位置）と、周りに物が無い場所を用意した
- [ ] 設定ファイルのパラメータ（特に s₀ と Dynamic Method）を確認した
- [ ] `ExperimentData` フォルダに動作確認のデータが残っていない
- [ ] アンケート（各条件の評価、SSQ など）を用意した
- [ ] 同意書を用意した

### 5.2 被験者への説明（例）

先生のコメント「実験協力してくれる人にスムーズに説明できるように」への対応として、説明の例を載せます。
**研究の仮説（どの条件が良いはずか）は伝えない** ようにしてください（回答に影響するため）。

> 「これから VR のゴーグルをかぶって、周りの景色を見てもらいます。
> 景色の中には形の違うオブジェクトがいくつかあり、それぞれに3文字のアルファベットや数字が書いてあります。
> 頭を左右に動かして、**すべてのオブジェクトの文字を声に出して読み上げてください**。
> 見え方が少しずつ違う条件をいくつか体験してもらい、条件が終わるごとにアンケートに答えてもらいます。
> 気分が悪くなったら、すぐに言ってください。いつでも中止できます。」

### 5.3 実験の進め方

| 手順 | 実験者の操作 | 被験者 |
|---|---|---|
| 1 | Experiment シーンを開き、▶（Play）を押す | — |
| 2 | 実験者パネルに被験者ID（P01, P02, …）を入力。**条件の順番** の表示を確認して「実験を開始」 | — |
| 3 | 被験者に HMD をかぶってもらう | VR 内の説明パネルを正面に見る |
| 4 | 被験者が正面を向いたら **Space**（自動でリセンターされ、試行が始まる） | 文字を読み上げる |
| 5 | 実験者パネルに出る「表示中の文字」と、被験者の読み上げを照合する | — |
| 6 | すべて読み終えたら（または制限時間が来たら）**Space** で試行終了 | — |
| 7 | HMD を外してもらい、この条件のアンケートに回答してもらう | アンケート |
| 8 | 手順3〜7を、全試行（練習 + 3条件）が終わるまで繰り返す | — |
| 9 | 「全試行が終了しました」と出たら終了。次の被験者は「次の被験者へ」を押す | — |

### 5.4 キー操作の一覧

| キー | 使える状態 | 動作 |
|---|---|---|
| Space | 待機中 / 試行中 | 試行の開始 / 終了 |
| R | いつでも | リセンター（いまの向きを正面にする） |
| 1 / 2 / 3 | 待機中 | 次の試行の条件を変更（1：通常、2：制御一定、3：動的制御）。**動作確認用。本番では使わない** |
| H | いつでも | デバッグ表示の切り替え |

> **Quest 本体のリセンター**（Meta ボタン長押し）と、このシステムのリセンター（R キー）は別物です。
> このシステムは試行の開始時に自動でリセンターするので、普段は R キーを押す必要はありません。

### 5.5 条件の順番について

被験者ID の数字で、3条件の並べ方6通りが順番に割り当てられます。

| 被験者番号 | 順番 |
|---|---|
| 1, 7, 13, … | 通常 → 制御一定 → 動的制御 |
| 2, 8, 14, … | 制御一定 → 動的制御 → 通常 |
| 3, 9, 15, … | 動的制御 → 通常 → 制御一定 |
| 4, 10, 16, … | 通常 → 動的制御 → 制御一定 |
| 5, 11, 17, … | 制御一定 → 通常 → 動的制御 |
| 6, 12, 18, … | 動的制御 → 制御一定 → 通常 |

被験者を **6 の倍数の人数** 集めると、すべての順番が同じ回数になり、「慣れ」や「疲れ」の影響が打ち消されます。

## 6. 出力されるデータ

保存先：プロジェクト直下の **`ExperimentData/`**（メニュー **DynamicHighlights → 実験データのフォルダを開く** で開けます）

> 被験者のデータは個人情報にあたるため、Git には入らない設定（`.gitignore`）にしてあります。
> バックアップは研究室のルールに従って別の場所に取ってください。

### 6.1 フレームログ（`P01_T1_DynamicControl_20261119_153000_frames.csv`）

1試行につき1ファイル。1行が1フレームです。

| 列名 | 単位 | 意味 |
|---|---|---|
| frame | — | Unity のフレーム番号 |
| trial_time_s | 秒 | 試行開始からの時間 |
| r_deg | 度 | 実視線方向 r |
| v_deg | 度 | 仮想視線方向 v |
| offset_deg | 度 | v − r |
| omega_deg_per_s | 度/秒 | 角速度 ω |
| s | — | 傾き s |
| c | — | 制御強度 c = (1 − s)/(1 − s₀) |
| pitch_deg | 度 | 上下の向き（上がプラス） |
| gaze_target | — | 見ているオブジェクトの ID（見ていなければ空） |

### 6.2 まとめファイル（`P01_summary.csv`）

被験者ごとに1ファイル。試行が終わるたびに、オブジェクトの数だけ行が追加されます。

| 列名 | 意味 |
|---|---|
| participant | 被験者ID |
| trial | 試行番号（練習 0、本番 1〜3） |
| is_practice | 練習なら 1 |
| condition | NoControl / FixedControl / DynamicControl |
| dynamic_method | Absolute / Incremental |
| target_id | オブジェクトの ID（Before_R, Highlight_R, After_R, Before_L, …） |
| label | 表示していた文字（読み上げの照合用） |
| first_reach_s | 初めて見た時刻 [秒]（見なかったら −1） |
| dwell_s | 見ていた合計時間 [秒] |
| trial_duration_s | 試行の長さ [秒] |
| phi_deg, w_deg, s0, omega0_deg_per_s, tau_s, N, symmetric | その試行で使ったパラメータ |
| frames_file | 対応するフレームログのファイル名 |

## 7. グラフの作り方

### 7.1 r-v-ω の3次元グラフ（先生のコメントへの対応）

1. メニュー **DynamicHighlights → r-v-ω グラフ用CSVを出力** を押します。
2. `ExperimentData/mapping_grid_phi45_w20_s00.5_omega090.csv` のようなファイルができます（列：omega_deg_per_s, s, c, r_deg, v_deg）。
3. Python で次のように描けます。

```python
import pandas as pd
import matplotlib.pyplot as plt

df = pd.read_csv("ExperimentData/mapping_grid_phi45_w20_s00.5_omega090.csv")

# 3次元グラフ（横：r、奥：ω、縦：v）
fig = plt.figure()
ax = fig.add_subplot(projection="3d")
ax.plot_trisurf(df["r_deg"], df["omega_deg_per_s"], df["v_deg"], cmap="viridis")
ax.set_xlabel("r [deg]"); ax.set_ylabel("ω [deg/s]"); ax.set_zlabel("v [deg]")
plt.show()

# v-ω グラフ（r を固定して、ω によって v がどう変わるか）
for r in [15, 25, 35, 45, 55, 65, 75]:
    d = df[df["r_deg"] == r]
    plt.plot(d["omega_deg_per_s"], d["v_deg"], label=f"r={r}°")
plt.xlabel("ω [deg/s]"); plt.ylabel("v [deg]"); plt.legend(); plt.show()
```

### 7.2 実験中の r-v の軌跡（フレームログから）

```python
df = pd.read_csv("ExperimentData/P01_T1_DynamicControl_..._frames.csv")
plt.scatter(df["r_deg"], df["v_deg"], c=df["omega_deg_per_s"].abs(), s=2, cmap="plasma")

plt.colorbar(label="|ω| [deg/s]")

```

Excel の場合は、CSV を開いて r_deg と v_deg の列を選び、「挿入 → 散布図」で描けます。

## 8. 自動テストの実行

数式やプログラムを変更したら、テストを実行して壊れていないか確認してください。

1. **Window → General → Test Runner** を開きます。
2. **EditMode** タブ → **Run All**：数式のテスト（HighlightMapping、角速度、方式B）
3. **PlayMode** タブ → **Run All**：シーン全体の動作テスト（カメラの向き、CSV の保存、自動再生）

> テストは「正しく動いているか」を自動で判定するものです。カメラの動きを **目で見て** 確かめたいときは、
> テストではなく 3.5 の「カメラ挙動チェック」ウィンドウを使ってください。

すべて緑色のチェックになれば成功です。赤色になったテストがあれば、テスト名とメッセージを見て原因を調べます。

コマンドラインから実行する場合（Unity を閉じた状態で）：

## 9. よくあるトラブルと対処法

| 症状 | 原因と対処 |
|---|---|
| Play しても HMD に何も映らない | ① Quest Link が開始されているか確認。② Meta Quest Link が有効な OpenXR ランタイムになっているか確認（2.4）。③ Project Settings → XR Plug-in Management の Windows タブで OpenXR にチェックがあるか確認（無ければメニュー「XR（OpenXR）を設定」） |
| デバッグ表示の入力が「マウス模擬」のまま | HMD が Unity に認識されていません。上と同じ確認をしてください |
| 頭を回すと視界が2倍回る・制御が効いていないように見える | カメラに別のトラッキング用コンポーネント（Tracked Pose Driver など）が付いていないか確認。このシステムでは GazeDirectionController だけがカメラの向きを決めます |
| 日本語が □□□ になる | Windows に日本語フォント（游ゴシック・メイリオ）が無い可能性があります。`Util/JapaneseFont.cs` の候補にPCにあるフォント名を追加してください |
| デバッグ表示に赤字で「設定エラー」 | パラメータの制約（4.3）を満たしていません。φ, w, s₀ を見直してください |
| Console に「パラメータに問題があります」 | 同上 |
| オブジェクトの位置が φ と合っていない | φ や左右対称の設定を変えた後は、メニュー「実験シーンを作成」でシーンを作り直してください |
| CSV を Excel で開くと文字化けする | UTF-8（BOM付き）で保存しているので通常は大丈夫です。古い Excel の場合は「データ → テキストまたは CSV から」で UTF-8 を指定して開いてください |
| 方式B で、正面に戻っても v が 0° にならない | 方式B の性質です（解説資料の 4.2）。試行の開始時に自動でリセンターされます。途中で直したいときは R キー |
| 映像がカクカクする | Game ビューの Stats で FPS を確認。デバッグ表示（H で消せる）や、他のアプリを閉じると改善することがあります |
